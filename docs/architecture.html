Request Data Flow

1
User changes a filter
FilterBar.vue updates a reactive ref in useFilters() composable — e.g. selectedStatus = "Delivered", selectedPeriod = "Q2-2025". The composable is a singleton so all views share the same state.
2
View detects the change
The active view uses watch() on filter refs. When a ref changes it calls the relevant API function with getCurrentFilters().
const filters = getCurrentFilters() // → { warehouse: 'all', category: 'all', // status: 'delivered', month: 'Q2-2025' } const orders = await api.getOrders(filters)
3
api.js builds the HTTP request
URLSearchParams skips any filter value that is 'all', keeping requests clean.
GET http://localhost:8001/api/orders?status=delivered&month=Q2-2025
4
FastAPI route handler receives the request
Query params are extracted. The handler calls apply_filters() then filter_by_month() on the in-memory data loaded from JSON at startup.
filtered = apply_filters(orders, status="delivered") # → list comprehension, case-insensitive, O(n) filtered = filter_by_month(filtered, "Q2-2025") # → QUARTER_MAP['Q2-2025'] = ['2025-04','2025-05','2025-06'] # → keeps orders whose order_date contains one of those strings
5
Pydantic validates and serializes the response
The response_model List[Order] validates every item against the schema and serializes to JSON. FastAPI returns HTTP 200.
6
Vue updates the UI
Axios resolves the promise, the view sets data.value = response.data. Vue's reactivity system triggers a re-render — tables update, charts redraw, KPI cards recalculate via computed properties. The user sees filtered results immediately.

API Endpoints

GET /api/inventory All inventory items · filters: warehouse, category
GET /api/inventory/{id} Single inventory item by ID
GET /api/orders All orders · filters: warehouse, category, status, month (YYYY-MM or Q#-YYYY)
GET /api/orders/{id} Single order by ID
GET /api/demand All demand forecasts — no filters
GET /api/backlog Backlog items enriched with has_purchase_order flag
GET /api/dashboard/summary Aggregate KPIs · filters: warehouse, category, status, month
GET /api/spending/summary Procurement · Operational · Labor · Overhead totals + % change
GET /api/spending/monthly Monthly spending broken down by cost category
GET /api/spending/categories Spending by product category with percentage share
GET /api/spending/transactions Recent financial transactions
GET /api/reports/quarterly Quarterly rollups: orders · revenue · fulfillment rate
GET /api/reports/monthly-trends Month-by-month order count · revenue · delivery count
POST /api/purchase-orders Create a purchase order for a backlog item

Key Design Patterns

Singleton Composables (no Pinia)

useFilters(), useAuth(), useI18n() export module-level reactive refs. All views share the same state object — no store library needed for a demo.

Centralised API Layer

api.js is the single place for all HTTP calls. Components never import axios directly. Makes it easy to add interceptors, retries, or swap the HTTP client.

Quarter / Month Abstraction

QUARTER_MAP decouples quarters from month logic on the backend. filter_by_month() handles both "2025-04" and "Q2-2025" without extra parsing.

Hand-coded SVG Charts

Donut and bar charts are pure SVG inside components. No Chart.js keeps the bundle light and gives full style control without an external dependency.

Modal-first Detail Views

Inventory, backlog, cost, and order details open as overlays, not new routes. Parent passes the selected record as a prop; no extra route or navigation state needed.

In-memory Data (no DB)

All JSON files load once at server startup into Python dicts. Filtering is O(n) list comprehensions — fast enough for ~1K records, simple to change without migrations.
